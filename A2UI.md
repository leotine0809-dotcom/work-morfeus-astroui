# A2UI — adoption trigger (do NOT invent our own standard)

**Decision (2026-09-03):** astro-ui does **not** invent or maintain a wire-format standard. We keep a
**minimal, frozen, A2UI-shaped shim** (`spike/declarative-ui/src/a2ui/schema.ts` + `adapter.ts`),
isolated behind ONE adapter, and **adopt the real A2UI standard the moment it is actually adoptable
on our stack.** We own the *catalog + reliability gates* (the half A2UI leaves to you); we rent the
*format + renderer* (the commodity) as soon as the rental is real.

## Why not adopt A2UI today (checked 2026-09-03, repo `a2ui-project/a2ui`)
- Spec is **v0.9.1**; v1.0 is only a **release candidate**. README: *"Expect changes."*
- **No React renderer** — official renderers are Lit / Flutter / Angular; React is roadmap.
- **No published npm package** for the wire-format schema/TS types to depend on.
- → Adopting now = write a React renderer ourselves anyway **and** chase a pre-1.0 moving spec.
  Our frozen ~1-file shim is *less* maintenance than that, and is already shaped to migrate.
- Good: A2UI is **model-agnostic** (*"can be generated by any model"*) — Claude (`claude -p`) can
  emit the trees; **no Gemini lock-in.**

## The trigger — adopt A2UI when BOTH are true
1. **v1.0 is released (stable)** — no more "expect changes"; a published JSON Schema or TS types package exists to depend on.
2. **A React renderer ships** (official `@a2ui/react`-style package) OR published TS types we can bind a thin React renderer to.

Re-check the repo's Roadmap / Releases periodically for these two.

## The migration when the trigger fires (mechanical — 2 files)
1. Replace `a2ui/schema.ts` with the real A2UI schema/types (BoundValue / data-model / events).
2. Replace `pipeline.tsx` + `adapter.ts` + `@json-render/*` with A2UI's React renderer, registering
   **our catalog** as its "trusted, pre-approved component catalog."
3. **Carries over untouched:** the 13 components, their Zod prop schemas, and every reliability gate
   (`gates/contrast.mjs` · `theme.mjs` · `browser.mjs`). That is astro-ui's real value and is
   format-independent.

## What our shim deliberately shares with A2UI (so the swap stays mechanical)
- Flat node list + **id references** (adjacency list) — A2UI's model.
- `type` = a plain string discriminator (A2UI v1.0 style).
## What it deliberately omits (added by adopting real A2UI, not by us)
- BoundValue / data-model binding · streaming/event envelope · catalog negotiation.

**Rule:** keep the shim minimal and A2UI-shaped. Never grow it into a rich bespoke format — every
feature we'd add is a feature A2UI already specs. If a component needs more than flat JSON props,
that is a signal to adopt A2UI, not to extend the shim.
